# บทที่ 3 วิธีการดำเนินงาน

การจัดทำโครงงานเรื่อง **ระบบวางแผนมื้ออาหารและชุมชนออนไลน์ (Ginraide)** ผู้จัดทำได้กำหนดวิธีการและขั้นตอนการดำเนินงาน โดยยึดหลักการพัฒนาระบบวงจรชีวิตการพัฒนาระบบ (System Development Life Cycle : SDLC) ซึ่งมีรายละเอียดและขั้นตอนการดำเนินงานดังต่อไปนี้

## 3.1 ประชากรและกลุ่มตัวอย่าง
ในการประเมินประสิทธิภาพและความพึงพอใจของระบบ คณะผู้จัดทำได้กำหนดกลุ่มเป้าหมายดังนี้

**3.1.1 ประชากร (Population)** คือ
1) นักเรียน นักศึกษา และบุคคลทั่วไปที่ประสบปัญหาในการคิดเมนูอาหารในแต่ละวัน
2) ผู้ที่ต้องการประหยัดค่าใช้จ่าย หรือมีงบประมาณจำกัดในการซื้ออาหาร (เช่น อาหารในร้านสะดวกซื้อ)
3) ผู้ที่ต้องการนำวัตถุดิบเหลือในตู้เย็นมาประกอบอาหารเพื่อลดขยะอาหาร (Food Waste)
4) ผู้ดูแลระบบ (Admin)

**3.1.2 กลุ่มตัวอย่าง (Sample)** คือ
คัดเลือกแบบเจาะจง (Purposive Sampling) แบ่งเป็น
1) กลุ่มผู้ใช้งานทั่วไป (นักเรียน นักศึกษา หรือบุคคลทั่วไปที่สนใจทดลองใช้งาน) จำนวน 25 คน
2) กลุ่มผู้ดูแลระบบ (Admin) จำนวน 5 คน
รวมทั้งสิ้น 30 คน

## 3.2 เครื่องมือที่ใช้ในการดำเนินงานโครงงาน
แบ่งออกเป็น 3 ส่วนหลัก ได้แก่ ฮาร์ดแวร์ ซอฟต์แวร์ และเครื่องมือประเมินผล

**3.2.1 เครื่องมือด้านฮาร์ดแวร์ (Hardware)**
1) คอมพิวเตอร์โน้ตบุ๊ก สำหรับการเขียนและพัฒนาระบบ
2) สมาร์ทโฟน สำหรับการทดสอบการแสดงผลหน้าจอแบบ Responsive Design

**3.2.2 เครื่องมือด้านซอฟต์แวร์และเทคโนโลยี (Software & Technology)**
1) **Front-end Development:** ใช้เทคโนโลยี React.js (ผ่านเครื่องมือ Vite) ร่วมกับ Tailwind CSS สำหรับการออกแบบหน้าจอส่วนติดต่อผู้ใช้งาน (UI) และใช้ Framer Motion สำหรับการทำแอนิเมชัน
*เหตุผลที่เลือกใช้:* React.js ช่วยให้สามารถแบ่งองค์ประกอบหน้าเว็บ (Component) กลับมาใช้ซ้ำได้ ทำให้ระบบประมวลผลได้เร็ว ส่วน Tailwind CSS ช่วยให้การจัดรูปแบบหน้าตารองรับทุกขนาดหน้าจอ (Responsive) ได้ง่ายและสวยงาม
2) **Back-end & API:** ใช้ Node.js ร่วมกับ Express.js สำหรับสร้าง RESTful API และใช้ Prisma ORM ในการจัดการโครงสร้างและดึงข้อมูลจากฐานข้อมูล
*เหตุผลที่เลือกใช้:* Node.js ทำงานแบบ Asynchronous เหมาะกับระบบที่มีผู้ใช้งานหลายคนพร้อมกัน และ Prisma ORM ช่วยให้การเขียนคำสั่งจัดการฐานข้อมูลมีความปลอดภัยและลดข้อผิดพลาด (Type-safe)
3) **Database Management:** ใช้ระบบจัดการฐานข้อมูล Supabase (PostgreSQL)
*เหตุผลที่เลือกใช้:* PostgreSQL เป็นฐานข้อมูลเชิงสัมพันธ์ที่มีประสิทธิภาพสูง รองรับโครงสร้างข้อมูลที่ซับซ้อนของระบบชุมชน (ผู้ใช้ โพสต์ คอมเมนต์) ได้ดี และ Supabase มีบริการคลาวด์ที่เชื่อมต่อได้รวดเร็ว
4) **Development & Deployment Tools:** ใช้โปรแกรม Visual Studio Code สำหรับเขียนโค้ด, GitHub สำหรับจัดการเวอร์ชัน (Version Control) และใช้ Vercel สำหรับให้บริการระบบบนอินเทอร์เน็ต (Deployment)
*เหตุผลที่เลือกใช้:* Vercel รองรับการโฮสต์แอปพลิเคชัน React และ Node.js ได้อย่างมีประสิทธิภาพ ทำให้นำระบบขึ้นออนไลน์ได้สะดวกรวดเร็ว

**3.2.3 เครื่องมือที่ใช้ในการเก็บรวบรวมข้อมูล**
แบบสอบถามความพึงพอใจของผู้ใช้งานระบบ (Questionnaire) แบบมาตราส่วนประมาณค่า (Rating Scale) 5 ระดับ ตามวิธีของลิเคิร์ท (Likert Scale)

## 3.3 ขั้นตอนการดำเนินการศึกษา (SDLC)
ผู้จัดทำได้แบ่งขั้นตอนการดำเนินงานออกเป็น 5 ระยะ ดังนี้

**3.3.1 การศึกษาความต้องการของระบบ (Requirement Analysis)**
1) ศึกษาปัญหา: ผู้คนมักประสบปัญหา "ไม่รู้จะกินอะไรดี" มีงบจำกัด หรือมีวัตถุดิบในตู้เย็นแต่คิดเมนูไม่ออก และขาดพื้นที่ในการแลกเปลี่ยนสูตรอาหารที่ตอบโจทย์ชีวิตประจำวัน
2) รวบรวมความต้องการ:
- **ผู้ใช้งานทั่วไป:** ต้องการค้นหาเมนูคอมโบเซเว่นตามงบประมาณ, ค้นหาเมนูอาหารทำเองจากวัตถุดิบในตู้เย็น, ตั้งกระทู้ถาม-ตอบ, รีวิว, คอมเมนต์, กดไลก์ และเข้าสู่ระบบได้อย่างปลอดภัย
- **ผู้ดูแลระบบ (Admin):** ต้องการแดชบอร์ดสรุปสถิติ, จัดการเพิ่ม/ลบ/แก้ไข ข้อมูลเมนูคอมโบ สินค้าเซเว่น เมนูตู้เย็น วัตถุดิบ และสามารถแบนผู้ใช้ที่ทำผิดกฎชุมชนได้

**3.3.2 การออกแบบระบบ (System Design)**
1) **การออกแบบสถาปัตยกรรม (Architecture Design):** ใช้โครงสร้างแบบ Client-Server โดย Frontend ส่ง Request ไปยัง Backend API เพื่อติดต่อกับฐานข้อมูล Supabase
2) **การออกแบบฐานข้อมูล (Database Design):** ออกแบบ ER-Diagram ที่เชื่อมโยงตารางหลัก ได้แก่ ผู้ใช้งาน (Users), โพสต์ (Posts), คอมเมนต์ (Comments), การกดไลก์ (Likes), เมนูคอมโบ (ComboRecipes), สินค้า (Products), เมนูทำเอง (FridgeMenus) และ วัตถุดิบ (FridgeIngredients)
3) **การออกแบบผังการทำงาน (Process Design):** สร้าง Sitemap และ Flowchart เพื่อกำหนดทิศทางการเข้าถึงหน้าต่างๆ แบ่งสิทธิ์ตามบทบาท (User และ Admin)
4) **การออกแบบหน้าจอผู้ใช้งาน (UI/UX Design):** ออกแบบให้ใช้งานง่าย ทันสมัย รองรับการใช้งานผ่านมือถือเป็นหลัก (Mobile-first) และมีการแสดงผลแบบ 2 คอลัมน์สำหรับเมนู

**3.3.3 การพัฒนาระบบ (System Development)**
ดำเนินการเขียนโปรแกรมตามที่ได้ออกแบบไว้ โดยแบ่งเป็นโมดูลหลัก:
- โมดูลสมาชิกและการยืนยันตัวตน (Authentication)
- โมดูลค้นหาเมนูคอมโบและเมนูตู้เย็น
- โมดูลเว็บบอร์ด/ชุมชน (Community)
- โมดูลระบบจัดการหลังบ้าน (Admin Dashboard)

**3.3.4 การทดสอบระบบ (System Testing)**
1) **Unit Testing:** ทดสอบการทำงานของแต่ละฟังก์ชัน เช่น การคำนวณยอดไลก์ต้องไม่ติดลบ, การแสดงผลเมนูต้องไม่ทับกัน
2) **Integration Testing:** ทดสอบการเชื่อมต่อระหว่าง Frontend และ Backend เช่น เมื่อ Token หมดอายุ ระบบต้องแจ้งเตือนให้เข้าสู่ระบบใหม่
3) **User Acceptance Testing (UAT):** นำระบบให้กลุ่มเป้าหมายทดลองใช้งานจริงเพื่อหาข้อผิดพลาดก่อนนำไปใช้งาน

**3.3.5 การติดตั้งและใช้งานจริง (Deployment)**
อัปโหลดระบบขึ้นเซิร์ฟเวอร์คลาวด์ของ Vercel ทั้งส่วนหน้าบ้านและหลังบ้าน เพื่อให้ผู้ใช้สามารถเข้าถึงระบบ Ginraide ได้ผ่านอินเทอร์เน็ต

## 3.4 การเก็บรวบรวมข้อมูล
1) นำระบบ Ginraide ไปให้ผู้เชี่ยวชาญและกลุ่มตัวอย่างได้ทดลองใช้งาน
2) ให้ผู้ใช้งานประเมินความพึงพอใจผ่านแบบสอบถามออนไลน์ (Google Forms)
3) รวบรวมข้อมูลและข้อเสนอแนะที่ได้มาใช้ประกอบการสรุปผลและปรับปรุงระบบ

## 3.5 การวิเคราะห์ข้อมูลและสถิติที่ใช้
วิเคราะห์ข้อมูลแบบสอบถามด้วยโปรแกรมคอมพิวเตอร์ โดยใช้สถิติพื้นฐาน ได้แก่:
1) ค่าเฉลี่ย (Mean)
2) ส่วนเบี่ยงเบนมาตรฐาน (Standard Deviation: S.D.)

แปลผลคะแนนเฉลี่ย 5 ระดับ:
- 4.50 - 5.00 หมายถึง มีความพึงพอใจระดับ มากที่สุด
- 3.50 - 4.49 หมายถึง มีความพึงพอใจระดับ มาก
- 2.50 - 3.49 หมายถึง มีความพึงพอใจระดับ ปานกลาง
- 1.50 - 2.49 หมายถึง มีความพึงพอใจระดับ น้อย
- 1.00 - 1.49 หมายถึง มีความพึงพอใจระดับ น้อยที่สุด
