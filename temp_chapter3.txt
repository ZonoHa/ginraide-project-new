
บทที่ 3 วิธีการดำเนินงานการจัดทำโครงงานเรื่อง ระบบบริหารจัดการกิจกรรมวิทยาลัยอัจฉริยะ SAMS ผู้จัดทำได้กำหนดวิธีการและขั้นตอนการดำเนินงาน โดยยึดหลักการพัฒนาระบบวงจรชีวิตการพัฒนาระบบ (System Development Life Cycle : SDLC) ซึ่งมีรายละเอียดและขั้นตอนการดำเนินงานดังต่อไปนี้ 3.1 ประชากรและกลุ่มตัวอย่าง ในการประเมินประสิทธิภาพและความพึงพอใจของระบบ คณะผู้จัดทำได้กำหนดกลุ่มเป้าหมายดังนี้3.1.1 ประชากร (Population) คือ        1) นักเรียนนักศึกษา วิทยาลัยเทคนิคนวมินทราชินีมุกดาหาร ทุกประเภทวิชาและทุกระดับชั้น       2) คณะกรรมการชมรม TO BE NUMBER ONE คณะกรรมการชมรมวิชาชีพและคณะกรรมการองค์การนักวิชาชีพในอนาคตแห่งประเทศไทย       3) ครูที่ปรึกษาชมรมวิชาชีพและชมรมกิจกรรม / ครูประจำชั้น       4) เจ้าหน้าที่งานกิจกรรม       5) คณะผู้บริหาร และหัวหน้างานกิจกรรม3.1.2 กลุ่มตัวอย่าง (Sample) คือ คัดเลือกแบบเจาะจง (Purposive Sampling) แบ่งเป็น        1) ผู้ดูแลระบบ คณะกรรมการองค์การฯ และเจ้าหน้าที่งานกิจกรรม จำนวน 5 คน       2) กลุ่มผู้ใช้งานทั่วไป (นักเรียนนักศึกษา วิทยาลัยเทคนิคนวมินทราชินีมุกดาหาร ทุกประเภทวิชาและทุกระดับชั้น) จำนวน 25 คน รวมทั้งสิ้น 30 คน3.2 เครื่องมือที่ใช้ในการดำเนินงานโครงงาน แบ่งออกเป็น 3 ส่วนหลัก ได้แก่ ฮาร์ดแวร์ ซอฟต์แวร์ และเครื่องมือประเมินผล 3.2.1 เครื่องมือด้านฮาร์ดแวร์ (Hardware)         1) คอมพิวเตอร์โน๊ตบุ๊ค จำนวน 1 เครื่อง - Intel Core i5 10300h 2.50 Turbo 4.50 GHz 4 Core 8 Thread - เครื่องมือด้านซอฟต์แวร์และเทคโนโลยี (Software &amp; Technology)         1) Front-end Development ใช้ภาษา TypeScript ร่วมกับ Framework Next.js และไลบรารี React โดยใช้ Tailwind CSS สำหรับออกแบบส่วนติดต่อผู้ใช้งาน นอกจากนี้ยังใช้ HTML5 QR Code สำหรับสแกนรหัสคิวอาร์ และ Leaflet ร่วมกับ React Leaflet สำหรับแสดงแผนที่และเลือกตำแหน่งกิจกรรม           เหตุผลที่เลือกใช้: เนื่องจาก Next.js และ React ช่วยให้สามารถแบ่งส่วนติดต่อผู้ใช้เป็น Component ที่นำกลับมาใช้ซ้ำได้ ทำให้พัฒนาและปรับปรุงระบบได้สะดวก ส่วน TypeScript ช่วยตรวจสอบชนิดข้อมูลและลดข้อผิดพลาดระหว่างการพัฒนา ขณะที่ Tailwind CSS ช่วยให้การออกแบบหน้าเว็บมีรูปแบบสม่ำเสมอและรองรับ Responsive Design ทำให้ระบบสามารถใช้งานได้อย่างเหมาะสมทั้งบนคอมพิวเตอร์ แท็บเล็ต และสมาร์ตโฟน        2) Back-end &amp; API ใช้ภาษา TypeScript พัฒนาระบบหลังบ้านด้วย Hono Framework และทำงานบน Bun Runtime สำหรับจัดการตรรกะทางธุรกิจและสร้าง RESTful API โดยใช้ Zod ตรวจสอบข้อมูล ใช้ JSON Web Token ร่วมกับ HTTP Cookie สำหรับยืนยันตัวตน และใช้ LINE Messaging API สำหรับส่งข้อความแจ้งเตือน           เหตุผลที่เลือกใช้: เนื่องจาก Hono เป็น Framework ที่มีขนาดเล็ก ทำงานรวดเร็ว และรองรับ TypeScript กับ Bun ได้ดี เหมาะสำหรับสร้าง RESTful API และ Middleware สำหรับตรวจสอบสถานะการเข้าสู่ระบบและสิทธิ์ของผู้ใช้ ส่วน Zod ช่วยตรวจสอบความถูกต้องของข้อมูลก่อนนำไปประมวลผลหรือบันทึกลงฐานข้อมูล ขณะที่ JWT และ HTTP Cookie ช่วยให้ระบบสามารถยืนยันตัวตนและควบคุมสิทธิ์ตามบทบาทของผู้ใช้งานได้อย่างปลอดภัย        3) Database Management ใช้ระบบจัดการฐานข้อมูล MySQL 8.4 และใช้ไลบรารี MySQL2 สำหรับเชื่อมต่อระหว่าง API Server กับฐานข้อมูล รวมถึงใช้ phpMyAdmin สำหรับตรวจสอบและบริหารจัดการข้อมูลระหว่างการพัฒนา           เหตุผลที่เลือกใช้: เนื่องจาก MySQL เป็นระบบฐานข้อมูลเชิงสัมพันธ์ที่เหมาะกับข้อมูลของระบบ SAMS ซึ่งมีความสัมพันธ์กันหลายส่วน เช่น ผู้ใช้งาน ห้องเรียน แผนกวิชา ชมรม กิจกรรม และประวัติการเข้าร่วมกิจกรรม โดยรองรับ Foreign Key, Index, Constraint และ Transaction ซึ่งช่วยรักษาความถูกต้อง ป้องกันข้อมูลซ้ำ และเพิ่มประสิทธิภาพในการค้นหาข้อมูล ส่วน MySQL2 รองรับการทำงานแบบ Asynchronous, Connection Pool และ Prepared Statement ทำให้การเชื่อมต่อฐานข้อมูลมีประสิทธิภาพและปลอดภัยมากขึ้น        4) Development Tools ใช้โปรแกรม Visual Studio Code (VS Code) สำหรับเขียนและแก้ไขซอร์สโค้ด ใช้ Docker Desktop และ Docker Compose สำหรับจำลองและควบคุมสภาพแวดล้อมของ Web Application, API Server, MySQL และ phpMyAdmin ใช้ Caddy สำหรับ Reverse Proxy และ HTTPS และใช้ Cloudflare Tunnel สำหรับเผยแพร่ระบบทดลองผ่านอินเทอร์เน็ต           เหตุผลที่เลือกใช้: เนื่องจาก Visual Studio Code รองรับภาษาและเทคโนโลยีที่ใช้ในโครงการ พร้อมมีเครื่องมือช่วยตรวจสอบข้อผิดพลาดและจัดการไฟล์ได้สะดวก ส่วน Docker Desktop และ Docker Compose ช่วยให้ทุกองค์ประกอบของระบบทำงานภายใต้สภาพแวดล้อมเดียวกัน ลดปัญหาความแตกต่างระหว่างเครื่องพัฒนาและทำให้ติดตั้งระบบได้ง่ายขึ้น ขณะที่ Caddy ช่วยให้ระบบรองรับ HTTPS ซึ่งจำเป็นต่อการใช้งานกล้องและตำแหน่ง GPS ผ่านเว็บเบราว์เซอร์ และ Cloudflare Tunnel ช่วยให้สามารถทดสอบระบบผ่านอินเทอร์เน็ตได้โดยไม่ต้องเปิดพอร์ตของเครื่องเซิร์ฟเวอร์โดยตรง 3.2.3 เครื่องมือที่ใช้ในการเก็บรวบรวมข้อมูล แบบสอบถามความพึงพอใจของผู้ใช้งานระบบ (Questionnaire) แบบมาตราส่วนประมาณค่า (Rating Scale) 5 ระดับ ตามวิธีของลิเคิร์ท (Likert Scale)3.3 ขั้นตอนการดำเนินการศึกษา (SDLC) ผู้จัดทำได้แบ่งขั้นตอนการดำเนินงานออกเป็น 5 ระยะ ดังนี้ 3.3.1 การศึกษาความต้องการของระบบ (Requirement Analysis)         1) ศึกษาปัญหาของระบบบริหารกิจกรรมวิทยาลัย SAMS กระบวนการบันทึกข้อมูลการเข้าร่วมกิจกรรมในปัจจุบันยังคงพึ่งพาระบบเอกสารและการเช็คชื่อแบบเดิมเป็นหลัก ส่งผลให้เกิดความล่าช้า ข้อมูลตกหล่น การตรวจสอบความถูกต้องทำได้ยาก และมักเกิดปัญหาการเช็คชื่อแทนกัน นอกจากนี้ การสรุปผลประเมินการผ่านเกณฑ์กิจกรรมของผู้เรียนในแต่ละภาคเรียนยังต้องใช้ระยะเวลานาน ทำให้ไม่สามารถติดตามและช่วยเหลือผู้เรียนที่มีสถิติต่ำกว่าเกณฑ์ได้อย่างทันท่วงที         2) รวบรวมความต้องการของระบบบริหารกิจกรรมวิทยาลัย SAMS  - นักเรียนนักศึกษา ต้องการตรวจสอบกิจกรรม สแกน QR Code เพื่อเช็กชื่อ ดูประวัติและเปอร์เซ็นต์การเข้าร่วมกิจกรรม รวมถึงตรวจสอบสถานะกลุ่มเสี่ยงของตนเอง - คณะกรรมการชมรมและองค์การนักวิชาชีพ ต้องการสร้างและจัดการกิจกรรม กำหนดสถานที่และช่วงเวลาเช็กชื่อ สร้าง Dynamic QR Code และตรวจสอบรายชื่อผู้เข้าร่วมกิจกรรมของชมรมที่รับผิดชอบ - ครูที่ปรึกษาและครูประจำชั้น ต้องการติดตามผลการเข้าร่วมกิจกรรมของนักศึกษาในความดูแล ตรวจสอบนักศึกษากลุ่มเสี่ยง และดาวน์โหลดหรือรับรายงานผ่าน LINE - เจ้าหน้าที่งานกิจกรรม ต้องการจัดการข้อมูลผู้ใช้ ห้องเรียน แผนก ชมรม และกิจกรรม รวมถึงควบคุมการเช็กชื่อ ตรวจสอบผลการเข้าร่วม และจัดทำรายงาน - คณะผู้บริหารและหัวหน้างานกิจกรรม ต้องการดูข้อมูลภาพรวมผ่าน Dashboard เปรียบเทียบผลการเข้าร่วมกิจกรรม การออกแบบหน้าจอผู้ใช้งาน (UI/UX Design):** ออกแบบ Wireframe หน้าจอต่างๆ ให้ใช้งานง่ายและรองรับอุปกรณ์พกพา 3.3.3 การพัฒนาระบบ (System Development) ดำเนินการเขียนโปรแกรม (Coding) ตามที่ได้ออกแบบไว้ โดยแบ่งการพัฒนาเป็นโมดูล (Module) เช่น โมดูลจัดการสมาชิก, โมดูลระบบตะกร้าสินค้า, โมดูลชำระเงิน, และโมดูลติดตามสถานะ (Order Tracking) 3.3.4 การทดสอบระบบ (System Testing) 1) Unit Testing  ทดสอบการทำงานทีละโมดูลว่าไม่มีข้อผิดพลาดเบื้องต้น (Bug) 2) Integration Testing ทดสอบการทำงานร่วมกันของระบบ เช่น เมื่อลูกค้าสั่งอาหาร ข้อมูลต้องไปปรากฏที่หน้าร้านอาหารและระบบของพนักงานจัดส่งอย่างถูกต้อง 3) User Acceptance Testing (UAT) ให้กลุ่มตัวอย่างทดลองใช้งานจริง เพื่อตรวจสอบความถูกต้องและรับข้อเสนอแนะมาปรับปรุง 3.3.5 การนำไปติดตั้งและใช้งานจริง (Deployment) อัปโหลดระบบขึ้นสู่เซิร์ฟเวอร์จริง (Web Hosting หรือ Cloud Server) และตั้งค่าโดเมนเนม เพื่อเตรียมความพร้อมสำหรับการนำเสนอและให้กลุ่มตัวอย่างเข้าใช้งาน 3.4
